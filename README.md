# Кредитный скоринг клиентов банка для выдачи кредита
## Цель: классифицировать клиентов банка для выдачи или невыдачи кредита
Модель  должна определить объекты(клиентов) в одну из групп: дефолт - не дефолт, на основе данных ей признаков(возраст, доход, кол-во других займов и тд.)
## Стек: 
### Среда программирования: 
Python 
### Библиотеки: 
sklearn, pandas, numpy, catboost, matplotlib, seaborn
## Данные: 
Датасет "Give me some credit" с гитхаб/соревнования кэгл: https://github.com/DrIanGregory/Kaggle-GiveMeSomeCredit
количество классов - два, количество признаков - 10(не считая целевую переменную), количество объектов - ~150 тысяч.
В датасете присутствуют пропуски, аномальные значения, имеется дисбаланс классов(примерно 1 к 13).
В коде датасет загружается из гугл драйва.
## Пайплайн:
### Предобработка
Заполнение пропусков медианой, устранения аномальных значений через медиану.
### Модель
Градиентный бустинг catboost, так как не нуждается в кодировке категориальных данных.
### Подбор параметров: 
Через Optuna, так как дешевле GridSearch
### Оценка качества:
Precision и recall, посмотреть насколько хорошо модель вылавливает и распределяет объекты и ROC-AUC, чтобы посмотреть как модель находит положительный класс(редкий в этом случае).
## Результаты:
Модель выдала ROC-AUC ~0.87 на тренировочном датасете и 0.86 в submission на кэгл. Precision и recall для положительного класса сильно разнится от порога(либо большой precision либо большой recall).
При пороге 0.2 precision =0.39, recall =0.5,
При пороге 0.4 precision = 0.53, recall =0.27. И так далее при возрастании порога recall уменьшается, а precsion растет.

## Вывод
Стандартная ситуация для кредитного скоринга. Встает выбор: либо precision, либо recall. Тут ничего не поделать, стоит решать что важнее для банка, уловить больше дефолтов, но потерять несколько клиентов, или пропустить много дефолтов, но дать услугу клиентам, которые вернут займ.
Уделить больше внимания предобработке: из-за пропусков в двух важных признаках сильно портятся другие. Например, ежемесячный доход и DebtRatio, из-за нанов в доходе, DebtRatio местами вырастает до аномальных значений, что сбивает модель. Посмотреть как DebtRatio зависит от дохода и на основе этого скорректировать данные - в теории, это должно увеличить точность.
